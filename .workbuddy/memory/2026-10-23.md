## 评估「USB 直连 Hermes 替代 Wi-Fi」可行性（同日）

- 固件只有 WebSocket 传输：`hg::Transport` 唯一实现是 `port_ws.cpp`（esp_websocket_client），USB Serial/JTAG 仅用于 esp_console（port_console.cpp）；无 serial transport、无 tinyusb → 现固件下 USB 直连不可行。
- 连接闸门：`app.on_network(true, detail)` 由 port_wifi 的 GOT_IP 触发（main.cpp:167、app.cpp:259/324），USB 方案必须自己 post NetUp，否则停在 NoNetwork。
- 协议细节：子协议 `hermes-gadget.v1`、token 在 hello JSON 里（不在 HTTP header），ws buffer 4096 → 主机侧 relay 只需普通 WS 升级即可透传。
- 本机实测环境：**Win10 企业版 LTSC 19044** → WSL mirrored 网络不可用（需 Win11 22H2+）；`.wslconfig` 无 networkingMode（默认 NAT，localhostForwarding=true）；8765 仅 `127.0.0.1` 可达（`wslrelay.exe` pid 9512）；`192.168.1.4:8765` 实测不通；无 usbipd。
- 结论排序：① 0 改动先修 WSL 暴露（portproxy 到 192.168.1.4 + 防火墙）与免配网（Kconfig 预置 SSID/密码或 USB console `wifi` 命令）；② 要 USB 就做 SLIP 串口隧道（保留 303A:1001 console 与烧录，relay 跑在 Windows，连 127.0.0.1:8765）；③ USB-NCM 需牺牲 USB-JTAG console 且 Windows 驱动+静态 IP 更麻烦；④ usbipd 透传 COM 进 WSL2 不推荐。

## NCM 实测否定 + 方案选定（同日）

- 板上现跑 tusb_ncm 示例，USB 口为网卡模式，COM5 消失（现存 COM3/COM4）；设备 `USB\VID_303A&PID_4000&MI_00`（tinyusb 默认 PID_4000）状态 Error。
- **决定性实测**：`DEVPKEY_Device_ProblemCode = 28`（无驱动）；`C:\Windows\System32\drivers\UsbNcm.sys` **不存在**；`C:\Windows\INF\usbncm.inf` 在但无对应二进制；`rndismpx.sys` 也缺（`usb8023.sys` 在）。→ Windows 10 LTSC 19044 缺 NCM 驱动二进制，靠改 INF 无解，只能第三方签名驱动或换系统；RNDIS 也可能同样缺件。
- 决定：放弃 USB-NCM，采用串口隧道（方案 A）；若只是"免配网"则用 Kconfig 预置 SSID，不必改 USB。
- 刷回注意：merged image 写 0x0 会清 NVS（设置/配对/身份）；进 ROM 模式=按住 BOOT 插线再松手，USB-Serial/JTAG 会重新枚举为 COM5。
