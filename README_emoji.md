# 小墨 · 纯表情包说明书（feat/moji-emoji-only）

> 20 张表情全部由 `hg::emoji::draw()` 用 Canvas 几何直绘，240 px 设计帧；不嵌 GIF、不引解码器，
> 所以每个表情只花几十字节代码而不是几百 KB 位图。下表 GIF 是**固件渲染器实际输出**
> （`tools/dump_emoji.cpp` + `tools/make_emoji_gifs.py` 生成，见 §五），不是设计稿示意。
> 连接中的黄圈不在渲染器里——它由 `Ui::draw_emoji` 贴着玻璃画，dump 时按同一几何补画，
> 所以这张 GIF 也会转。帧数是实测值：生成脚本把 20 帧里连续相同的帧并掉，
> 静止的脸帧数就少（断开只有 1 帧，睡觉 3 帧，思考 8 帧，中性 14 帧），
> 每张 GIF 的帧数见下表「帧数」列。

## 二、设计理念

1. **眼是主角，其余是optional。** 20 张里 8 张保持同一对「高瘦椭圆（50×100，(72,112)/(145,112)）」
   底眼：中性、聆听、思考、说话、连接中是整对，Hi 是这对眼的放大版，傻与眨眼是左眼
   （傻的右眼是 `<`，眨眼的右眼一眨一开）。其余 12 张的眼睛本身就是表情（><、爱心、
   怒眼、实心圆、压扁、星星、∪∪ 闭眼、XX、半沉眼、墨镜盖住），靠配饰区分的是思考的
   三个点、聆听的三条弧、说话的音量柱、连接的黄圈、傻的 ? 眼、酷的墨镜。
   表情不靠嘴——圆屏上嘴是很容易画坏的东西。
2. **心情不讲逻辑，讲可见度。** 大笑、喜欢、生气、震惊、尴尬、兴奋这六张直接用**眼睛本身**当表情，
   这类眼睛（><、爱心、怒眼、实心圆、压扁、星星）在全局 blink 里豁免——它们一闭眼表情就没了。
   豁免清单：`Happy / Sleeping / Disconnected / Laughing / Loving / Excited / Bored / Cool / Hi`。
3. **同一个 240 px 帧，zoom 1.2。** 所有几何以 240 设计帧为单位从 Canvas 原语绘出
   （`FacePen` 统一做缩放映射），`HG_EMOJI_ZOOM` 默认 1.2：脸盒 200 px 时实际画到 240。
   连接上的黄圈是唯一例外——它是**玻璃的边缘语言**，所以画在面板帧里贴着屏幕走。
4. **不做用不到的事。** 不嵌 941 KB GIF、不加 assets 分区、不写动画脚本：每个表情就是一段
   几何 + 一个相位函数（`gif_phase`），动效成本是每帧十几次 fill 而不是一帧图片。

## 三、静息不无聊

长时间待机时，**每 20 秒随机换一张静息表情**，直到无聊、睡着——这是「20 张不能只停在一两张」的底线。
轮换池七张（不会连出同一张）：中性（扫视）、酷（墨镜）、开心（沙锤）、
喜欢（爱心）、兴奋（星星眼）、Hi（射线）、傻（问号）。无聊不在池子里，
她是自己无聊出来的，不是轮出来的。

  0–140 s   每 20 s 随机从上面七张里挑一张
  140 s     无聊（半沉眼），轮换停了
  180 s     睡觉（3 分钟；z 的短暂出现是这一轮的下限）

提醒三连（8 秒一窗，结束回静息；完成那张亮 5 秒）：

  绑授权 → 傻（?）
  绑选择 → 震惊（!!）
  绑完成 → 兴奋（星星眼）

## 四、AI 挑表情（已接）

脸由谁定，只看一个顺序（`firmware/core/src/ui.cpp` 的 `emoji_look()`；
设备自己知道的状态压过 AI 猜的脸，AI 猜的脸只压过屏幕推断）：

**链路 → 唤醒应答 Hi → 提醒（绑授权 Silly / 绑选择 Shocked）/ 办完 Excited →
回复心情 → 播报中 Speaking → AI 指定 → 屏幕**

- 链路：连接中/网络异常 → 连接中（转圈），离线 → 断开（XX）；
- 唤醒应答：喊小墨、她说「我在」时是 Hi（眼睛放大再射线），不是 Speaking 的音量柱——
  打招呼不是说话，所以不张嘴；
- 提醒：绑授权 → 傻（?）、绑选择 → 震惊（!!），各 8 秒；事情办完 → 兴奋（星星眼），5 秒。
  提醒撞车时赢：播报中途来了提醒，脸也先让给提醒；
- 回复心情：见下文。心情盖得过 Speaking，但盖不过提醒；
- 播报中 Speaking：这句回复没有心情标签时，播报就配固定 20 帧音量柱；
- AI 指定：`gadget_face(look, seconds=8)` 是 agent（Hermes）的另一条表情入口——
  插件 `plugin/tools.py` 注册进 gadget 工具集，enum 列全 20 态，`hub.emote()` 发
  `{"emote": {"look": "...", "ttl_s": 8}}`；固件 `h_emote()` 把名字映射成 `emoji::Look`，
  存 `named_look_` 并按 ttl 过期。播报中到达的指定脸先进 `pending_look_`，播完才起算 ttl，
  嘴和声音不会错开；
- 屏幕：都没轮到时按屏幕推断——聆听 / 思考 / 播报（没在说话就是中性）/ 出错 Sad，
  兜底中性。按 BOOT 取消当前回合时，XX 脸（断开）亮 3 秒。

### 回复心情：`[mood:X]` 标签

`gadget_face` 是一次 8 秒的闪现，播报完才起算；**回复当时的脸**由心情标签定。
LLM 在每句回复正文最前面加一个标签，例如 `[mood:laughing] 哈哈，这个好笑`：

- 插件 `plugin/tools.py:parse_mood_tag()` 认这个标签：只认 20 态的名字，
  `surprised` 当 `shocked` 的别名；只取第一个标签，其余的也一并剥掉；
  未知名字记一条 warning 并丢掉，**绝不静默变中性**
  （固件 `look_from_name` 对不认识的名字会回落中性，所以插件是最后一道闸）；
- 插件 `plugin/hub.py:send_reply()` 只在**最终回复**（`interim == false`）解析：流式
  delta 可能把标签拆成两半，解析了也没用。标签从正文里剥掉再发，`mood` 随回复 JSON
  一起发到设备；固件 `h_reply()` 读它，整句播报期间（`Responding`）都戴这张脸，
  取代通用的 Speaking 波形脸。下一轮 `turn.start` 清掉心情，没标签就一切照旧；
- 标签**永远不会被读出来**：`adapter.py` 的两条 TTS 路（`_synthesize_auto_tts`、
  `prepare_tts_text`）都在合成前把标签剥掉。

带上这张链路后，标签能点的 12 张（happy / laughing / loving / excited / winking /
silly / embarrassed / sad / angry / shocked / bored / cool）就不再是摆设：
AI 按对话内容挑，`listening`/`speaking`/`connecting`/`disconnected` 仍归设备自己管。

### 加到 `gadget-emoji` profile 里的原文

profile 在用户自己的机器上，不在仓库里——下面这段**原样贴进 profile 的 SOUL.md**
（或 system prompt），不要改名字、不要加名字：

```markdown
## 表情心情（小墨的脸）

每次回复时，在回复正文最前面加一个心情标签，格式 `[mood:名字]`，例如 `[mood:laughing] 哈哈，这个好笑`。
标签会被自动去掉，不会显示也不会读出来；小墨在播这句回复时就戴这张脸，直到这句播完。
只用下面这些名字（不要自创，拼错会被直接丢掉）：

- happy 开心：事情办成了、对方高兴
- laughing 大笑：真的好笑、幽默
- loving 喜欢：爱意、夸奖、暖心的话
- excited 兴奋：大好消息、爆发式的好结果
- winking 眨眼：俏皮、开玩笑、意会
- silly 傻：没听清对方说了什么，要请对方再说一遍
- embarrassed 尴尬：听清了，但答不上来、回复出了问题、得道歉或说没听懂
- sad 难过：坏消息、安慰对方
- angry 生气：拒绝、对方做错了要指出
- shocked 震惊：出乎意料的消息（也可以写 surprised，会自动当成 shocked）
- bored 无聊：没什么可说的、例行公事
- cool 酷：淡定、一切尽在掌握

没有明显情绪就不加标签（别为了加而加）；一轮回复只加一个，放在最前面。
```

### 已接：空回复 → 傻

回复空无一物（LLM 返回空串/空白）时，插件在 `adapter.py` `edit_message` 的 finalize
分支里认出来：改发兜底文案“这条回复是空的，请再问一次。”，并显式带 `mood="silly"`，
整句播报期间戴傻脸。傻的定义就是“没听清对方说了什么，要请对方再说一遍”，
兜底文案里的“请再问一次”就是它的定义原文——所以挂傻不挂尴尬。
尴尬留给 LLM 在正文里道歉时的心情标签（`[mood:embarrassed]`）。
注意：这只抓**真正空**的回复；整句只是工具调用标记的那种，旧版靠
`strip_tool_tokens` 剥离后判定，新版没有这层剥离（`for_device` 不剥标记），
所以不在本次范围。

## 五、复现

```bash
# 先编一次 host 版 core 库（固件 agent 的构建目录还在就直接用；/tmp 被清过就重建）：
cmake -S firmware -B /tmp/hg-v2-fix-test -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/hg-v2-fix-test --target hg_core   # 产物 core/libhg_core.a
g++ -std=c++17 -I firmware/core/include tools/dump_emoji.cpp \
    /tmp/hg-v2-fix-test/core/libhg_core.a -o /tmp/dump_emoji
mkdir -p /tmp/emoji-frames   # dumper 不会自己建目录
/tmp/dump_emoji                      # 20 looks × 20 frames → /tmp/emoji-frames/*.ppm
python3 tools/make_emoji_gifs.py     # .ppm → assets/emoji/*.gif
```

生成脚本把 20 帧里连续相同的帧并掉再写 GIF，所以帧数因脸而异（见 §一「帧数」列），
不是每张都是 20 帧；内容没变的脸重新生成后像素也一样（逐帧比对过）。
连接中的黄圈由 `Ui::draw_emoji` 画，`tools/dump_emoji.cpp` 按同一几何
（中心 (120,120)、r=113、宽 12、每帧转 18°、黄 `rgb565(255,205,0)`）补画，
否则这张 GIF 只有眨眼的 2 帧、圈不会转。
