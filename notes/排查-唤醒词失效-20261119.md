# 唤醒词失效与「任务完成提示」消失：插件版本错配（moji-emoji-v2 刷机后）

记录时间：2026-11-19 10:45（刷 v2 固件与实测之后）

## 现象

- 20 态表情正常，USB 链路正常，设备 `online (paired)`。
- 喊「你好小墨」「小墨小墨」屏幕与声音都没有反应。
- 回合结束后没有完成提示（hook 丢失）。

## 证据链

1. 唤醒引擎本身正常：启动日志 `hg.wake: wake word ready: mn5q8_cn, threshold 0.20,
   frame 512 samples at 16000 Hz`，`resume: tap on`，`afe frame: 512 samples`，
   `MODEL_LOADER: Successfully load srmodels`（model 分区刷写成功）。
2. 模型确实命中，但被状态机拒掉：
   `hg.wake: hit: command 0 at 71 percent` → `hg: wake: command 0 at 71 percent` →
   `hg: wake: hit ignored (can_talk y, settings n, prompt n, mode 3)`。
   `Mode` 枚举 `app.hpp:367`：Idle=0 / Listening=1 / Thinking=2 / Responding=3。
   即设备卡在 `Mode::Responding`。
3. 进入 Responding 的路径不止回合：`app.cpp:1363` `h_audio_start` 收到任何音频流就置
   `Responding`（无条件）。
4. 退出 Responding 只有一个条件：`app.cpp:2908`
   `settled = turn_done_ || (reply_final_ && elapsed > kSettleAfterReplyMs)`。
   所以一段没有 `turn.start/turn.end` 包围的音频，播完也永久停在 Responding。
5. 卡住后链路自行超时重连：`hg: connection closed: server silent (replying)`，
   重连后 `mode_` 不重置，唤醒词继续被拒。
6. 版本错配是根因：生效插件 `~/hermes-sync/plugins/gadget` 原为 **0.4.0**（10-2x 的树），
   项目 `plugin/` 为 **0.6.0**。0.4.0 与固件 0.6 的回合/音频收尾不匹配。

## 追加：天气工具在 0.6 树里丢了（同日）

现象：TTS 说天气改为「中国天气网」的数据，不再走和风天气。

原因：`plugin/weather.py`（和风配方）在 HEAD 里，但 `plugin/tools.py` 没有
`WEATHER_SCHEMA` / `gadget_weather` / `weather_available`，`register_tools` 也不注册它。
Stage A 把本地改过的 `tools.py` 重置为 v0.6.0，注册代码随之丢失；`git log -S` 查不到
`gadget_weather`，说明它此前只活在生效目录 `~/hermes-sync/plugins/gadget`，从没进过仓库。

回植（`plugin/tools.py`）：
- `WEATHER_SCHEMA`（放 `FACE_SCHEMA` 之后）。
- `gadget_weather`：语音一行答案；`show=true` 时上卡，纯表情板改走 `shown_error` 说明是口播。
- `weather_available`：只查 key/host，不依赖 hub（板子没插也能报天气）。
- `register_tools` 里单独注册，`check_fn=weather_available`。
- 回归用例 `tests/test_plugin_weather.py`（5 条，含注册检查）。

验证：
- `weather.answer(days=1)` 实测返回「扬州 晴 10℃ 体感6℃ 西北3级 湿度36%；今天 少云 11/1℃」。
- `pytest tests/test_plugin_weather.py tests/test_weather.py tests/test_plugin_face.py` → 21 passed。
- 变异：删掉注册后 `test_the_weather_tool_is_registered_with_the_key_check` 变红并指出缺
  `gadget_weather`，还原后全绿。

环境变量：`QWEATHER_HOST` / `QWEATHER_KEY` / `QWEATHER_PLACE` 在
`~/.hermes/profiles/gadget/.env`；`weather.py:40` 的 `_env` 先读 `os.environ`，再走 Hermes 的
`get_provider_env`，所以 gateway 进程环境里没有这些变量也能读到。

## 追加二：中文播报里夹英文（同日）

现象：设备播报天气时夹进一个英文词（用户听成「EAPORT」）。

原因：Hermes 的 `tools/tts_text_normalize.prepare_spoken_text` 按英文习惯展开符号，实测：

```
IN : 扬州 晴 10℃ 体感5℃ 西西北3级 湿度37%；今天 少云 11/1℃；明天 晴 12/2℃
OUT: 扬州 晴 10℃ 体感5℃ 西西北3级 湿度37 percent；今天 少云 ℃；明天 晴 ℃
```

- `37%` → `37 percent`
- `11/1℃` 被当路径（`_IDENTIFIER_TOKEN_RE` 含 `/`）整段丢掉
- `2~11℃` → `2 about 11℃`

修复（插件侧覆盖，不改 Hermes 本体）：
- `plugin/textfmt.py` 新增 `spoken_symbols()`：`37%`→`百分之37`、`2~11`→`2到11`、`11/1`→`11到1`。
- `plugin/adapter.py` 的 `GadgetAdapter.prepare_tts_text()` 先跑它，再交给基类归一化。
- `tests/test_plugin_tts_text.py` 5 条（含整句用例）。

验证：`76 passed`（plugin_tts_text / plugin_weather / plugin_face / plugin_units / weather）；
端到端组合输出「湿度百分之37；今天 少云 11到1℃；明天 晴 12到2℃」，无 `percent`/`about`。
变异：关掉百分号规则后两条用例变红。

## 追加三：中文播报归一化两边同步（同日）

社区参考（都在 GitHub，均为「规则优先」的文本正则化，不引入神经网络）：

- `wenet-e2e/WeTextProcessing`（840★，Apache-2.0）：`tn/chinese` 规则集，数字/日期/时间/货币/度量/百分比/范围全覆盖，依赖 pynini。
- `speechio/chinese_text_normalization`（744★，MIT）：Python + thrax 两套实现，按类别给规则与语料。
- 结论：两家规则库对聊天场景都过重（pynini/thrax），但**符号表 + 数值范围**这一层可直接借用。

两边落地：

- 本仓 `plugin/textfmt.py::spoken_symbols`：百分号 `%`→`百分之`、范围 `~ ～ /`→`到`、
  符号表（‰ ± × ÷ ≠ ≤ ≥ → ⇒ ≈ ㎡ ㎥ ㎏ ㎝ ㎜）与 muse-tts 的同源同表。
  测试 `tests/test_plugin_tts_text.py` 6 条；`pytest` 插件相关 95 passed；变异后红。
- muse 仓 `tts-server/tts_server.py`（提交 `0e77338`，已推 main）：`speakable()` 增加数值范围规则，
  `_RANGE_RE`。腾讯云 124.220.19.238 上的 `muse-tts` 容器已用 `docker cp` + `restart` 生效，
  备份 `/opt/muse-tts/tts_server.py.bak-20261119-1120`；`/tts` 实测 200 / 26640 B / 首字节 0.40 s，
  `speakable("室温 5~10℃，湿度 37%，面积 12㎡")` → `"室温 5到10摄氏度，湿度 37%，面积 12平方米"`。

差异（有意保留）：

- `%`：Hermes 的 TTS 会读成 "percent"，所以在插件侧转「百分之」；Azure 自己读得对，muse 侧不转。
- `℃`：插件侧保留（Edge TTS 读「摄氏度」），muse 侧转成「摄氏度」（Azure 不稳）。

发现的不一致：腾讯云 `/opt/muse-tts/tts_server.py` 806 行，仓库 1096 行——线上比仓库旧约 290 行，
择时用 `tts-server/deploy.py` 重新部署一次再以仓库为准。
