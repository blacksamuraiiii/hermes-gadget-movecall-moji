# 吸收上游 v0.6.0：两段式计划与已完成状态

最后更新：2026-11-18

## 背景与结论

本仓从 Adolanium/hermes-gadget-sdk 分叉，做了两件上游没有的事：**有线（USB Serial/JTAG）
链路**和**纯表情渲染**（20 态，`emoji_face.cpp`）。分叉点 `469978c`（2026-10-21），
本地 145 个提交，上游 v0.6.0 已领先 643 个提交、405 个文件。

上游**完全没有** moji 板型、`emoji_face.*`、`robot_face.*`、`face_pen.hpp`——这部分是
本仓独有资产，合并时只会被"覆盖风险"，不会有上游修复。因此每次吸收上游，都是"把上游
整棵树拿过来，再把我们的东西重新接上去"，而不是普通的双向合并。

板上镜像存档：`dist/emoji-v1/`（app / bootloader / partition-table / ota_data_initial +
SHA256SUMS）。注意 `dist/` 里原有的 0.3.0 镜像**不是**纯表情版。

## 已定的四个决策

1. **保留 `emote` 作为唯一表情通道**；上游 `face.set`（neutral/happy/confused/alert/
   sleepy）映射成对 20 态的别名，让任何走官方动作的调用也能落到表情上。
2. **一切结构化内容都不宣告**：不宣告 `caps.card`、`caps.choice`、`caps.dashboard.v`、
   `caps.interpret`，屏上只有脸，其余退回语音。
3. **砍掉 CJK/16px 字表**：纯表情板不画任何文字，`CONFIG_HG_FONT_CJK` 关掉，不再维护
   `font_cjk_16.cpp` / `font_ascii_16.cpp` / `font_5x7.cpp` 这套本地重生成。
4. **继续默认 USB 链路**（`CONFIG_HG_LINK_USB_SERIAL=y`）。上游那批 Wi-Fi 健壮性修复
   对本板收益有限，优先级下调。

## Stage A：已完成（`51be7b8`）

把树变成"上游 v0.6.0 + 90 个本地独有文件"，可编译、可测试、可验证。

做法：55 个冲突文件统一取 v0.6.0；随后把**本地改过的 165 个文件全部重置为 v0.6.0**。
后者是必要的——自动合并会静默保留本地改动（`tests/test_face.py` 的断言还写着"五帧"、
`mascot_data.cpp` 还是本地五帧数据），只解冲突标记看不出来。

验证口径：`git diff --name-status v0.6.0` 除 `.gitignore` 外**全部是新增**（=上游没有的
文件），没有任何"修改"项，说明共享文件与上游逐字节一致。

顺带修的仓库卫生：

- `build-emoji/` + `build-host/` 共 317 个构建产物移出版本库（`--cached`，本地文件保留）。
  之前入库的旧 `hg_core_tests` 二进制已按新 ABI 失效，跑起来直接段错误——就是它。
- `tools/relay*.log` 四个运行日志移出版本库。
- `.gitignore` 补 `/build-emoji/`、`/build-host/`、`tools/relay*.log`。

Stage A 有意丢弃、**Stage B 不再回植**：

- 本地 mascot 五帧数据与 `mascot_data.cpp` 重生成。v0.6.0 的 `mascot.hpp` enum 已含
  `Happy`/`Sad`，而全仓没有任何代码引用这两帧，本地那份数据没有使用者。
- 16px CJK 字表与 `font_5x7.cpp` 改名（决策 3）。

Stage A 暂置、**Stage B 要回植或适配**：

- `tests/test_hub_utterance.py`：依赖 `hub.NO_SPEECH_NOTICE`，上游 0.6 把"无语音录音"
  改成了丢弃语义（#313），需要按新语义重写而不是照搬。
- `firmware/esp32/boards/movecall-moji-esp32s3/`、`partitions-moji.csv`：板型未注册时
  会被 `test_firmware_tools` 的板型清单测试判为不一致，随板型一起落回去。

## Stage B：待做（按此顺序，每步都要能编译 + 跑 734 例）

## 已知风险

- 上游 0.6 的功能默认"有文字屏"，moji 是无文字、无触摸、USB 链路——合并后要防
  "功能看起来来了，在这块板上其实全都不可见"的假象。凡是新增的 caps，一律不宣告。
- 生成物（字体、mascot 位图）的冲突会周期性复发。这次已经通过"砍掉本地字体重生成"
  消掉最大一处；mascot 数据也改回以上游为准，不要再手工改 `mascot_data.cpp`。
- 上游条目多为"仅主机测试/仅模拟器"，`face.set` 本身也没上过真机。moji 合并后仍需
  自己的硬件回归（烧写、配对、唤醒、20 态轮换、提醒三类表情）。
